# ip_cheker_2 — карта файлов и запуск

Бот проверяет доступность IPv4 и целых `/24`, ведёт историю, личный список мониторинга
и раз в час сообщает **в общий чат только об изменениях** статуса.

Стек: Python 3.11, aiogram 3.31.0. Данные — JSON-файлы, без БД.
ICMP — локальный `ping` через subprocess, **напрямую**; `PROXY_URL` относится только к связи бота с Telegram.

`keyboards` не знают про данные и сеть. Хендлеры не открывают файлы и не запускают subprocess напрямую.

## Запуск

```bash
python -m venv venv
venv\Scripts\activate          # Windows;  Linux/macOS: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env         # Linux/macOS: cp
# заполнить .env: TOKEN, ADMIN_ID, ALERT_CHAT_ID
python main.py
```

`.env`:

| Ключ | Смысл |
|---|---|
| `TOKEN` | токен бота |
| `ADMIN_ID` | твой Telegram id; `0` = админка выключена |
| `ALERT_CHAT_ID` | группа/канал для алертов (бот должен быть участником); `0` = не слать |
| `PROXY_URL` | `socks5://user:pass@host:port` — только для Telegram, на ping не влияет |
| `DATA_DIR` | папка данных, по умолчанию `data` |
| `PING_LIMIT` | стартовый лимит одновременных пингов (потом меняется в админке) |
| `CHECK_INTERVAL` | период мониторинга в секундах (3600) |
| `MAX_WATCH` | сколько IP можно держать в мониторинге одному пользователю |

Нужен системный `ping`: Windows — есть из коробки; Debian/Ubuntu — `apt install iputils-ping`.

## Решения, которые держат логику простой

- **Лимит пингов** — новый `asyncio.Semaphore` на каждый скан, поэтому `resize()` не нужен: изменение применяется со следующего скана.
- **Один скан на пользователя** — `BUSY: set` + `try/finally`, без TTL: флаг снимается и при ошибке, и при отмене.
- **Отмена** — `asyncio.Event`, а не `task.cancel()`: не нужно разбирать `CancelledError`.
- **Удаление IP** — `mon:rm:<индекс>` в списке нажавшего, а не упаковка адресов в 64 байта.
- **Цикл мониторинга** — один `while True` с `try/except` внутри: это и есть supervisor.
- **Сначала пингуем объединение всех IP один раз, потом решаем, что слать** — без вложенных циклов «юзер → его IP».
- **Результат ping** — по коду возврата (на Windows плюс `ttl=`), вывод не парсится.
- **Запись JSON** — `tmp` + `os.replace`, синхронно, без `await` внутри, поэтому корутины не могут перемешаться и `asyncio.Lock` не нужен. Если перейдёшь на асинхронные файлы — верни lock.
- **Статусы меняет только фоновый тик.** Ручная кнопка «Проверить сейчас» статусы не пишет, иначе она «съест» будущее изменение и алерт не придёт.
- **Middleware** берёт пользователя из `data["event_from_user"]`: у `Update` в aiogram 3 **нет** поля `from_user`.

## Что убрать из старого проекта

`utils/menu.py` (самодельное состояние — есть FSM), `utils/activity_logger.py` (есть `logging` + ротация),
`updates.jsonl` и его запись, `logging.log` из корня (логи теперь в `data/logs/`),
`handlers/middlewares.py` (переехал в `middlewares/users.py`), `delivery.py` / `config_core.py` (не нужны).
`settings.json` и все runtime-файлы — в `data/`, `venv/` и `__pycache__/` — в `.gitignore`.

## Windows-нюансы

- Флаги ping выбираются автоматически: `-n 1 -w 1000` против `-c 1 -W 1`.
- Windows может вернуть код 0 при «Destination host unreachable», поэтому там дополнительно требуется `ttl=` в выводе.
- `asyncio.create_subprocess_exec` работает на стандартном Proactor-цикле (Python 3.8+ по умолчанию) — ничего менять не нужно.
